## 0. TL;DR（结论）

1. **压力链是成立的，而且效应极大**：条件在“人类战团真的落在学习者本回合对位座位”上，
   三种配置的败率从对照 **21.0%** 升到 **84.8%–93.6%**（**+63.7…+72.5pp**，配对 95%CI
   不含 0），期望承受伤害 **+15.3…+15.8**（对照 3.16 → 18.5–19.0），学习者剩余存活随从
   **−2.7…−2.9**（3.02 → 0.12–0.31）。**预注册 P1 成立 → 排除分支 (a)。**
2. **瓶颈在“暴露”，不在“单次强度”**：训练配置下，学习者**每个 learner-turn** 真正
   在对手位遇到人类战团的概率只有 **4.59%（s10）/ 4.48%（A）/ 11.89%（B）**；
   每局至少遇到一次 ≈ **46.8% / 46.0% / 81.7%**。B 的注入量是 s10 的 2.5×，暴露是 **2.6×**
   ——投递是线性的，但**绝对值很低**。主指标 human 面板则是**每回合 7 席全注入（100%）**，
   两者不是同一个分布。
3. **早期信用没有被 λ 压没（按实际使用的 λ）**：γ=1、**λ=0.995** 下，t≤8 决策的终局奖励
   GAE 权重中位数 **0.319**，t7 升本决策 **0.349**（N 中位 265、t7 决策序号中位 45–50）。
   但**日志里 `ppo.config.lam=0.95`**；若真按 0.95 算，t≤8 权重中位数是 **8.3e-6**（完全压没）。
   **代码路径用的是 `--lam 0.995`（见 §2.6）**，日志值是 `PPOConfig` 未传 `lam` 的默认值，
   属于**日志/配置串接缺陷**，必须修。
4. **保真度有实质差异**：在 **460 个**我们自己的可信完整 EOT 快照上，完整状态注入 vs
   board-only 注入（同状态、同 RNG）败率差 **+5.1pp**（同帧口径）/ **+6.7pp**（真实管线口径），
   95%CI 均不含 0；45% 的帧带金色随从、97% 带关键词、72% 带手牌，board-only 全部丢失。
   **预注册 F1 成立 → 分支 (c)：保真度扩展。**
5. **重要的方向性限定**：board-only 让对手**更弱**（+5～7pp 是“完整状态更强”），所以
   保真度缺口对训练压力是**保守偏差**——补保真度只会让压力更大，不能解释“注入更多却没帮助”。
   报告同时给出剂量与信用两侧的边界；下一轮如果只做一件事，应优先**提高训练暴露/分布对齐**
   （见 §3.3）。

## 1. 方法与预注册判据

### 1.1 冻结轨迹（`stage_trajectories`）

- s10 模型在 CPU 上以 eval 方式（`PPOEvaluator` + `PPOSelfPlayPolicy`，temperature=1.0、
  `move_guard=0`、无梯度、无 MCTS）跑 **620 局**大厅轨迹（`seed=910000+i`，每局到终局）。
- 大厅是**无注入**的 `s10 vs 7×引擎 bot`：这是配对设计的对照世界（注入在快照处施加）。
- 每条轨迹预抽一个目标 turn `t∈[6,15]`（独立 RNG `seed^0x5EED5EED`）。到达该 turn 起点时
  （任何座位行动前）保存：`state_json`（8 人容器）、学习者本回合对位 `next_opponent`、
  以及**战斗前**的学习者/对手完整 `player_json`（学习者的战团取 `last_board`，含
  end-of-turn 效果；对手取该座位 bot 行动结束后的状态）。
- 有效快照 **521 / 620**（≥512）。失败：`ghost_opponent` 57（本回合打幽灵，无对手座位）、
  `game_over_before_turn` 25、`learner_dead` 17。
- 学习者战团强度 p50 **449**（p10 103 / p90 1168）；对位 bot 战团强度 p50 **240**。

### 1.2 配对战斗（`stage_battles`）

对每个快照 × 三种配置（`s10=p90×2×0.3`、`A=auto×2×0.3`、`B=auto×3×0.5`）：

- **对照**：同快照、同战斗 RNG 种子、不注入；
- **注入（条件）**：`Game.inject_board` 在**战斗时刻**把对位座位战团替换成该配置在该 turn
  采到的人类战团（p90 / auto），即“命中即 100% 暴露”的条件效应；
- 每对 **64 次独立重播种**（引擎 `combat_preview`，trial i 的 rng = `seed^(K·(i+1))`，
  两臂同 seed → 逐 trial 配对），记录胜/负/平、造成/承受伤害、剩余存活随从（24 个 trial 的
  帧口径，另从 `last_frame.boards` 数 `hp>0`）。
- 另做**真实管线臂**：turn 起点注入（`p=1`，条件在命中）→ 该座位本回合照常 bot 行动 →
  用战斗前战团重播种。这是训练里真正发生的事（注入后 bot 还会买随从）。

### 1.3 暴露（`stage_exposure`）

按训练同款采样语义做 300 次/快照的 Monte Carlo：镜像先占（3 席、p=0.3、实测 apply 率
0.559）→ 人类战团从 7 个非学习者座位随机抽 `seats` 个 → 每个独立掷 `p` → 再乘该 run 实测的
`applied/attempt`（s10 0.580 / A 0.579 / B 0.598）。命中 = 学习者本回合对位座位 ∈ 人类实际
注入集合。**自洽校验**：模拟命中率 × 7 席 × 每局 turn 数 vs 实测 `applied/game`，误差 ≤ 7%。

### 1.4 信用（`stage_signal`）

用本审计自己采的 521 条轨迹的逐决策 `(turn, action, value)` + 终局名次，独立实现
`compute_gae`（与 `hsbg/az/train/ppo.py:compute_gae` 同式），γ=1、λ∈{0.995, 0.95}：

> **为什么不直接用训练 rollout**：s10 的 rollout buffer 没有落盘（`runs/az_entity_s10/_proc_tmp`
> 为空，`_weights/` 只是共享池权重），history 只保留每 iter 聚合。所以这里用**冻结 s10 策略
> 重采**的逐决策 value 重算——GAE 结构与 λ 与训练一致，差异在轨迹分布（无注入大厅、更长）。

- 终局奖励 `R=u(rank)∈[-1,1]` 只写在该座位 episode 末步；`done` 处 `next_value=0`（无 bootstrap）；
- 终局奖励对第 k 步的**线性信用权重** = `(γλ)^(N-1-k)`；
- 拆分 `A_k = A_k^R + A_k^V`：`A_k^R = w_k·(R−V_{N-1})`，`A_k^V` 为价值 bootstrap 项；
- 另从 `runs/az_entity_s10/history.jsonl` 统计截断/掩码/更新幅度。

### 1.5 保真度配对消融（`stage_fidelity`）

可信完整快照 = `runs/library/snaps_champ/*.json.gz` 里我们自己的 **EOT 快照**（含完整
`Player`：board+hand+counters+golden+attachments）。取 t∈[6,15] 且有战团的 **460 帧**。
每帧配一个同 turn 的轨迹容器（学习者不变），固定播种，两个口径：

- **同帧口径**：两臂都用该帧完整 `player_json`；board-only 臂再把 board 换成
  `inject_board(card,atk,hp)`（金色卡降为基础卡 cid，与真实人类观测的信息量一致）。
- **真实管线口径**：完整状态臂 = 完整帧；board-only 臂 = 容器里该座位的当前局状态 +
  只注入人类观测 board（无 hand/hero/powers 真值）。

### 1.6 预注册判据（跑数前写死，见 `decide_branch`）

| 判据 | 定义 |
|---|---|
| **P1 压力有效** | 任一配置：Δ败率(raw) ≥ **+0.05** 且 95%CI 下界 > 0，或 Δ承受伤害(raw) ≥ **+1.0** 且 CI 下界 > 0 |
| **C1 早期信用被压没** | λ=0.995 下 median GAE 权重(t≤8) < **0.10**，或 median 终端分量占比(t≤8) < **0.10** |
| **F1 保真度实质差异** | 可信快照上 Δ败率(full−board_only) ≥ **+0.05** 且 CI 下界 > 0，或 Δ伤害 ≥ **+1.0** 且 CI 下界 > 0 |

判定顺序：`not P1 → (a)`；`C1 → (b)`；`F1 → (c)`；否则 `(b)`（早期信用都没了，补保真度也不会被学到）。
**“不显著 ≠ 无效”**：所有判据都报效应量 + 配对 95% bootstrap CI。

### 2.5 早期 GAE 信用（γ=1）

| λ | median w(t≤8) | median w(t7 升本) | w(t≤8) p10 / p90 | 终端分量占 \|A\| 中位 | median w(全部决策) |
|---|---|---|---|---|---|
| **0.995（实际）** | **0.319** | **0.349** | 0.184 / 0.488 | **14.6%** | 0.506 |
| 0.95（日志值） | **8.3e-6** | 2.1e-5 | 3.0e-8 / 6.5e-4 | 1.4e-5 | — |

- 轨迹 N（学习者决策数）中位 **265**（p10 181 / p90 373）；t7 出现于决策序号中位 **45**
  （p10 35 / p90 58）。**73.1%** 的局在 t7 有升本动作（中位序号 50）。
- 因此 **λ=0.995 下 t7 升本 → 终局奖励的信用权重 ≈ 0.35**（约衰减 3×），**没有“被压没”**；
  但终端分量只占早期 advantage 的 **14.6%**，其余是价值 bootstrap 项（零均值噪声）——
  对“信用分配太稀疏”是**弱支持、未达预注册阈值**。
- **λ 配置不一致（需修）**：`history.jsonl` header 记录 `--lam 0.995`，但每条 `ppo.config.lam=0.95`。

  → `process_pool.py:388`），trainer 直接用预计算的 `batch.advantages`（`ppo.py:1478`）。
  **真实 GAE λ=0.995；`ppo.config.lam=0.95` 是日志缺陷。** 若真按 0.95，上表第二行就是灾难。

## 3. 分支判定

### 3.1 预注册判据逐条

- **P1 = true**：三种配置全部满足（败率 +5pp 且 CI 下界 > 0；承伤 +1.0 且 CI 下界 > 0）。
  → **排除 (a)**。
- **C1 = false**：median w(t≤8) = **0.319**（阈值 0.10）；median 终端分量占比 = **0.146**（阈值 0.10）。
  → 不选 (b)。（**边界提示**：终端分量 14.6% 距 15% 只差 0.4pp；若把阈值放到 15%，会翻到 (b)。
  另外若 GAE 真按日志的 λ=0.95，C1 会以 8.3e-6 碾压式成立——所以请务必先修 λ 日志。）
- **F1 = true**：管线口径 Δ败率 **+6.71pp [4.95, 8.55]**；Δ承伤 **+0.95 [0.75, 1.16]**。
  → **选 (c)**。

### 3.2 落点：**(c) 保真度扩展**

按预注册规则，结论是 **(c) 完整状态 vs board-only 有实质差异 → 保真度扩展**。证据：

1. 460 帧可信完整快照上，完整状态让学习者败率再高 **5.1–6.7pp**（CI 不含 0），承伤 +0.77…+0.95；
2. 每帧平均丢 **0.64 个金色随从、54 keywords bits、3.3 个 attachments、2.1 张手牌**；
   45%/97%/72% 的帧分别含金色/关键词/手牌；
3. 真实人类数据没有这些字段 → 这部分压力在训练里**系统性缺失**。

### 3.3 这个结论“不是全部”——必须一起读的三条限定

1. **保真度偏差是保守方向**：board-only 让对手更弱（完整状态更强）。所以补保真度**只会加大**
   训练压力，不会解释“注入更多 → 面板不升”。它使 §2.1 的 +64…+73pp 成为**下界**。
2. **真正的剂量问题在暴露**：每 learner-turn 4.6–11.9% vs 面板 100%。B 的 2.5× 注入量只换来
   2.6× 暴露与 +4.4pp/每 turn 的期望败率（s10 3.33 → B 7.70pp/turn），远不足以把策略从
   “对 bot 1.77 rank”推到“对 7 席人类 6.4 rank”。**若只做一件事，应先做分布/剂量对齐**
   （提高 seats/p 或改用整局轨迹池），而不是先扩隐藏状态。
3. **信用侧是边界态**：λ=0.995 权重 0.32 不算被压没，但终端分量只占早期 advantage 的 14.6%，
   且训练局只有 197.7 个决策——若按日志的 λ=0.95 会瞬间变成 8e-6。**先修 λ 日志/传参**，
   再评估是否需要 λ>0.995 或分层回报。

### 3.4 建议的后续顺序（按证据强度）

1. **修 `ppo.config.lam` 日志串接**（`PPOConfig` 显式传 `lam=args.lam`），确认实际 GAE=0.995；
2. **提高训练暴露/对齐分布**：至少在小规模 A/B 上把“每 learner-turn 命中率”从 ~5% 拉到
   ≥30–50%（例如 seats=4–5、p=0.8–1.0，或直接用整局 human-board 轨迹池），先看 human 面板
   是否可动；
3. **保真度扩展**：把 golden/keywords/counters/hand 尽量还原（真实人类不可得 → 用我们自己的
   EOT 快照做“完整状态注入”的训练臂，或对真实观测做 keyword 先验推断），预期压力再 +5–7pp；
4. **信用**：λ 日志修好后复算；若仍无改善，再考虑 λ→0.997/0.999 或按 turn 分层回报。

## 4. 局限（如实）

1. **轨迹大厅是“无注入”对照世界**，不是 s10 训练时的镜像+人类混合大厅。它不是训练分布的
   无偏样本；训练局更短（197.7 vs 265 decisions）→ 训练里 t7 的信用权重只会**更高**，所以本文
   的信用估计偏保守。压力侧的方向不能先验断定（训练大厅对手更强，但能活到 t 的局也是筛选后的）。
2. **暴露是模拟 + 实测校验**：座位抽样按训练同款语义（`random_seats` 从 7 个非学习者座位抽，
   含已死座位；镜像优先与 apply 率用 history 实测），与实测 `applied/game` 误差 ≤7%；
   但配对并非严格均匀（避免上回合对手），仍可能带来 ~5% 的偏差。
3. **保真度消融只用我们自己的 EOT 快照**（隐藏真值已知）；真实人类观测的隐藏真值**不可得**，
   所以“人类注入究竟丢了多大压力”**数据不足**，只能给机制量级与方向。
4. **剩余存活**用 24 个 trial 的最后一帧计数（`hp>0`），是 64 个战斗种子的子样本；
   均值差与 CI 已按快照配对 bootstrap。
5. **池账本**：board-only 注入到“非本局”的 8 人容器时，`inject_board` 的 `pool_balance_ok`
   在 1563 个臂里 1266 个为 false（新实体 `pool_copies=0`、旧 board 归还共享池）。只影响池账本，
   **不影响战斗数值**；训练时容器就是本局，故不复现。
6. 本审计**不重跑** human 面板、不训练、不用 GPU；所有战斗都是引擎 `combat_preview` 的
   冻结反事实。
7. 轨迹策略用 temperature=1.0 采样、`move_guard=0`（与 `quality_monitor.py`/公开评测同口径），
   不是训练时的 `move_guard=1` 行为；对**配对差**无影响，对学习者战团分布有轻微影响。
