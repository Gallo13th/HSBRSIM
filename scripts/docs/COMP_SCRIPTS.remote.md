## 2. 触发条件（每套显式）

| 触发 | 条件（`CompPolicy` 实现） | 动作 |
|---|---|---|
| **进入** | `t ≤ 7` 且商店/手牌出现核心卡；多套同时可行时按 **(已有核心数×3 + 商店核心×1.2 + tier 够得着×1 − 0.15·(t−6))** 排序取最大 | `--comp auto` 锁定该阵容；`--comp B` 立即锁定 |
| **坚持** | 核心在场上 **且** 载体在场上 **且** 载体吃到 ≥N 次 buff（落点计数 `casts_on_aim`） | 所有法术/buff 只打载体（`cast_on`）；买未拥有类型 |
| **退出** | `t ≥ 10` 仍没有核心（`core_seen` 为空） | 放弃阵容，转通用铺场（按曲线升本 + 买最大身材）；`--comp A..N` 固定模式不退出 |

## 3. 脚本规则（六条，`scripts/comp_scripts.py`）

1. **商店有核心 → 买**（同名去重；手牌有空位；刷新 ≤4 次/回合，缺核心时 +6）。
2. **核心齐 → 所有法术只打载体**：`pending.kind == target` 时优先选 `aim_ids`（= 载体 ∪ `cast_on`）
   的 eid；无载体则留牌不打（手牌 ≥8 才强制清空）。
3. **优先买未拥有的种族类型**：`set(races) − 场上已有种族` 非空、且有空位时优先买（`type_min` 见 §1）。
4. **满场卖「无类型 / 无 buff 价值」者**：核心/载体永不卖；按 (有无类型, 身材) 取最弱；每回合 ≤2 张。
5. **无动作则刷新**（≤4 次/回合）。
6. **按曲线升本**：`EARLIEST_TIER = {2:3, 3:5, 4:6, 5:8, 6:10}`，且 `gold ≥ 升级价`、场上 ≥4 随从。
   升本优先于横向置换（4→5 要 8 金、5→6 要 10 金，漏掉这一回合就再也升不上）。

**两种执行模式**：`--pure` 纯手写经济（实测只有 bot 的 1/5，见 §4）；默认**混合**——阵容动作优先，
其余交给引擎 bot（经济/站位/三连兜底）。混合模式的动作合法率 1.000。

### 4.3 为什么达不到 1,500（归因）

1. **核心 tier 门槛 = 时间门槛**：5 本最早 t8–9（8 金）、6 本最早 t10–11（10 金），而 5→6 本后
   商店才可能出现核心。实测核心到手 p50 = **9–12 回合**，只剩 3–5 回合生长期。
2. **类型要求吃不到**：`one_minion_per_type` 用匹配，全类型载体（守门融合怪）**只算 1 种类型**，
   所以「载体吃满所有 buff」在引擎里只有「法术直接打载体」这一条路（Tea Set 每张只给载体 1 份）。
   实测落点占比 0–11%，身材占比 0–7% —— 用户的「≥50%」在这批阵容里不成立。
3. **经济不支持复利**：10 金/回合、法术 1–3 金、商店 8 格 ≈ 每回合 3–4 张法术；沙盒里
   `fixed 30 金/回合` 的 S3 能到 4,207，完整对局只剩 1/20（与 `docs/FULL_GAME_TRANSFER.md` 一致）。
4. **纯脚本经济更差**：`--pure` 实测 t15 Σ 46–50（J/I/A，30 局；名次 7.4–7.5），说明手写经济
   打不过引擎 bot，混合模式才有 bot 水平。

## 6. 是否值得做 BC 教师？

**不值得（完整对局口径）**：最强阵容终局 Σ 292 ≈ bot 252、t15 Σ 249 < 当前策略 564；
「核心卡 + 载体 + 类型」这套人类先验在 10 金/回合的经济里没有兑现窗口。可复用的只有
`comp_action` 的三条优先级（买核心 / 法术只打载体 / 买缺的类型）——作为**推理期的
先验偏置**（`archetype_bias` 式加权）比作为 BC 教师更合适。

**若要做教师，先把环境改对**（与 `docs/FULL_GAME_TRANSFER.md` §3 同结论）：
① 沙盒跑 `--gold-profile` 真实曲线 + `--gold-cap 0`；② 把「升本」当显式目标（tier 奖励）；
③ 用 `--comp auto` 的状态分布采教师轨迹，而不是沙盒状态。
