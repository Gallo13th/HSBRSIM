# AutoTavern 论文如何使用人类数据（核对 docs/AUTOTAVERN_PAPER_TRAINING.md §1–8）

> 来源：arXiv:2610.33845v1（Changlian Ma, Limin Wang，2026-10-24）。§9–10 已过时，只用 §1–8。
> 结论先行：**论文没有用人类"动作"做 BC；人类数据主要作为"对手牌面库"（states）使用。**

## 1. 论文用了哪些人类数据

- **人类统计**：顶尖人类的种族占比、升级曲线、购买率、**分回合的 warband 强度**（§3/附录 C）。
- **录制对局（replay）**：与统计一起构造 **library entry = 某座位在某一回合的牌面**（board + hand +
  hidden counters）。
- **不是**动作级数据（论文全文没有"人类动作 BC / 行为克隆"的描述）；**没有**用人类数据做价值/奖励校准。

## 2. 具体用法

| 用法 | 是否使用 | 论文依据 |
|---|---|---|
| ① BC 预训练（人类动作） | **否** | 训练是纯 PPO；人类数据只进对手库 |
| ② **作为对手注入（library seats）** | **是（主用法）** | §6：*"Rather than self-play, the learner faces seven library seats … each turn, a seat takes a board … from a library built from statistics of top human players"* |
| ③ 价值/奖励校准 | **否** | 奖励=终局名次效用；价值头端到端学 |
| ④ 初始分布/探索引导 | **否** | 课程从零开始（简化规则→全内容→玩家视角→吃鸡目标→library 对手） |
| ⑤ 评估基线 | **是（exam library）** | 每评测点 24,576 局=3 个未见 seed×8,192；exam 库不参与训练（twin 库）；交付门 G4 要求 unseen-seed 复查 |

## 3. 数据规模 / 训练阶段 / 消融

- **library 条目数/池规模：未给出**；重校准节奏：20 天内 **14 次**（按天梯实际对手重校准）。
- 对手库在课程中出现在"吃鸡目标（按人类统计拟合的对手）"之后；**exam 库永不训练**。
- **消融（Table 3，同起点同预算各 150 iterations）**：
  | 对手 | 主 exam 吃鸡率 | 更难 exam 吃鸡率 |
  |---|---:|---:|
  | 未校准 library | 20.9% | 10.3% |
  | **校准后 library** | **27.2%** | **13.5%** |
  ⇒ **对手校准是论文称的"最大单项收益"**（+6.3 / +3.2 个百分点）。
- 另有一条与"人类数据"无关但必须知道：**搜索拷贝局面若不重播种 RNG 会"看到未来"**（+23.6 分假象，
  重播种后 −0.65±1.14）。

## 4. 与我们做法的差异

| 维度 | 论文 | 我们（HSBRSIM 现状） |
|---|---|---|
| 人类数据形态 | 牌面状态（对手库） | 吃鸡局**动作**（BC，764→1,242 行）+ 人类状态校准价值 |
| 用途 | **对手注入**（训练世界） | ① 动作模仿（s46/s49）；② 价值标签（scaling_value） |
| 评估 | 未见 seed 的 exam 库（24,576 局/行） | 12 跨 seed 起点 + s37 配对（规模小） |
| 结论 | 用"状态"改对手世界收益最大 | 用"动作"BC 收益有限（s46–s50 均未跨 seed 泛化） |

**含义**：我们的 BC 路线与论文相反——论文证明**"改对手/改世界"比"教动作"更有效**；我们的
s49b/s50 结果（多 seed BC + 价值奖励仍只有 671417-t9 能滚）也印证"教动作"上限有限。

## 5. 三条可直接借鉴的具体做法

1. **赢家校准的对手牌面库（最优先）**
   - 做什么：把 `runs/human_play/` 的吃鸡/前二局按回合切片成 board+hand，作为 `HumanBoardPool` 的
     注入源（我们已有 p0.9 注入机制），并按"实际对局中遇到的强度"周期重校准。
   - 数据：现有 32 个 replay（11 个吃鸡、10 个 seed），每局 ~14 回合 ⇒ ~150 个回合牌面。
   - 预期：论文同口径 +3~6 个点吃鸡率；对我们的直接收益是"训练分布更像真实对局"。
   - 成本：低（pool 注入已实现；只需按 placement 过滤 + 切片）。

2. **exam 库纪律（防止 winner's curse）**
   - 做什么：把种子分成 train / exam 两组，**exam 种子永不进训练**；每次交付在 exam 上跑
     24,576 局量级（我们可用 3 个未见 seed × 8,192）。
   - 数据：seed 列表 + 评测脚本（现有 human_panel_eval 可复用）。
   - 预期：避免"挑 snapshot 高估"（论文：+1.2–2.1 分高估 → unseen −0.7）；我们的跨 seed 12 点
     评测就是雏形，需要把"exam seed"显式隔离。
   - 成本：低（跑数时间）。

3. **一步前瞻 + 多重战斗模拟（重播种 RNG）**
   - 做什么：前瞻时对每个候选动作不仅用价值函数，还**用引擎模拟 N 次战斗**（论文用 256），
     且**每个 copy 必须重播种 RNG**（否则"看到未来"，收益是假的）。
   - 数据：现有引擎 + `game.copy()`；我们已有 1 步前瞻原型（s51）。
   - 预期：比纯价值前瞻更稳（论文 TavernBench 0.03s/题）；但注意我们的 s51 已发现 1 步前瞻
     收益小——加战斗模拟可能才够。
   - 成本：中（模拟 256 次 × 候选 = 每决策 ~秒级；需限制在最关键决策）。

## 6. 一句话

**论文的"人类数据"是 opponent-library（状态），不是动作 BC；最大单项收益来自"把对手校准成
人类强度"。我们应把人类 replay 先用于"对手库/评测库"，动作 BC 只作辅助。**
