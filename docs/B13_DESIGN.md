# B13：合并路线 1（配套强制）+ 路线 2（4 输出终局头）

起点 = B12 的 300M 权重；预算 300M；lr 重置 2.5e-6 退火；其余沿用 B12 配方
（强制升本 ≤5、ceiling 辅助头、`MULT,GROW,ENGINE` 买卡、`protect=MULT`、ban 加重护手、
5 席 human-board p0.90 full、λ=0.995）。

## 路线 1：放大器 → 配套核心"必须买"

`data/comp_cards.json` 增 `partners` 表（3 个放大器 → 30 张配套核心，按卡池可用性过滤）：

| 放大器 | 配套（节选） |
|---|---|
| 布莱恩·铜须 | 热气球测绘员 / 守门融合怪 / 海藻护卫 / 魔网浮灵 / 龙族看护员 / 英勇的巢母 |
| 达卡莱附魔师 | 小瞎眼 / 邪火咒龙 / 黑暗傀儡师 / 梦魇侵蚀怪 / 神秘的克熙尔 / 转运构筑机 |
| 提图斯·瑞文戴尔 | 断手被遗忘者 / 木乃伊工匠 / 丧钟死灵 / 永恒骑士 / 巨狼戈德林 / 永恒大亨 |

触发条件（**全部满足**才改写掩码）：场上已有放大器 + 商店有该放大器的配套卡 + 买得起且合法
+ 该卡 `own < max_copies`。

**六道闸门**（任一不满足 → 完全交回模型）：

| 闸门 | 默认 | 参数 |
|---|---:|---|
| 血量 > health_floor | 12 | `--comp-buy-health-floor` |
| 回合 ≤ late_turn | 17 | `--comp-buy-late-turn` |
| 已承诺阵容 < 2 | 2 | 内置 |
| **tier ≥ 4** | 4 | `--comp-buy-partner-tier-min` |
| 每回合强制次数 ≤ 2 | 2 | `--comp-buy-partner-max-per-turn` |
| 同卡张数 < max_copies | 2 | `--comp-buy-max-copies` |

另有 `--comp-buy-partner-mode soft`：触发时额外放行"结束回合"，模型可拒绝；`--comp-buy-partner 0` 一键关闭。
实测触发率极低（6 局 1420 决策中 0 次），因为需要"放大器已在场 + 商店恰好有配套"。

## 路线 2：ceiling 头 2 → 4 输出

| 输出 | 目标 | 损失 |
|---|---|---|
| 0 | `log1p(终局盘面 Σatk+hp)` | smooth_l1 |
| 1 | 终局 tier / 6 | smooth_l1 |
| 2 | 终局是否持有放大器（0/1） | BCE（有正样本时） |
| 3 | 成长斜率 `log1p(终局) − log1p(t15)` | smooth_l1 |

collector 在每局首次 `turn≥15` 记录盘面强度，局末回填 `final_has_amp` / `final_growth`；
旧 2 维头可平滑升级（前两行继承，后两行零初始化）。

### 发现并修复的 plumbing 漏洞（重要）

B13 前 130M 的 checkpoint 里 ceiling 头权重是 `[18.47, 0, 0, 0]` —— **只有第 0 维在学**。
根因是三处字段传递都没接新目标：

1. `build_batch_from_records`（records 路径）
2. `build_batch_from_arrays`（arrays 路径）
3. `process_pool.py` 的 worker 打包 + 合并白名单（硬编码字段表）

修复见提交 `f82cb02`；修复后 batch 的四个目标齐全。**B13 本轮因 trainer 早于修复启动，
路线 2 实际未生效**，需下一轮（B14）才真正开训。
