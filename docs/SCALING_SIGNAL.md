# 缩放行为的可学梯度：离线实证（不训练）

> **一句话结论：终局名次奖励对「缩放行为」的可学梯度在 s15 权重下不存在，而且 ∞ 金币课程
> 也没能把它变成可学**——不是奖励是阶梯函数（奖励对**相对身材**其实很敏感，r≈0.31–0.40），
> 而是**多施放一次法术几乎不换来身材**（1x：+3 Σ/次，CI 含 0；∞金币：−20 Σ/次，CI 不含 0），
> 且真正让法术复利的那几张「缩放载体」（5 张 × 普通/金色 + Felboar）在 500 局里只有
> **6–9%** 的局曾经上场。
> ∞金币把**水平**抬上去了（名次 5.27→2.70，t9 身材 0.62→2.03×真实 p50），但**信用分配**没变
> （r(施法,效用) 从 +0.115 变成 +0.022，两个 CI 都含 0）。

- 引擎 / 数据：`hsbg_engine` 37.0.0.255790（`source_hash b19ca68c1479a017`），默认 `RulesConfig`。
- 权重：**s15 step 301**（`runs/az_entity_s15/snapshots/step_000301/model.pt`，拷贝为
  `runs/scaling_signal/ckpt/s15_step301.pt`，md5 `fe5ab197374a12187cf2750f69c0b729`），
  训练在跑、**未 kill / 未重启 / 未占 GPU**（全程 `--device cpu`）。
- 全部数字 ← `runs/scaling_signal/{report.json,tables.md,panel.json,dose_detail.json}`；
  原始逐局数据 ← `runs/scaling_signal/rollouts/*.jsonl`（11 个 tag / **860 局实验**，1,260 行含复现副本）。

## 0. 判定表（先读这个）

| # | 假设 | 证据（本报告） | 判定 |
|---|---|---|---|
| 1 | 终局名次奖励对**缩放行为**提供可学梯度 | 1x：r(施法₉,效用)=**+0.115 [−0.023,+0.246]**；控制存活后 **−0.019 [−0.159,+0.114]**；存活到 t9 子集 **+0.056 [−0.092,+0.202]**；r(施法₉,Σ₉)=+0.124 [−0.010,+0.254]、r(施法₉,Σ₁₂)=−0.075 [−0.375,+0.223] | **不成立**（|r|≈0.1，全部 CI 含 0，且与「买身材」的 r(Σ₉,效用)=+0.314 相差 3×） |
| 2 | ∞金币课程把该信号变成可学（题面判据：r>0.3 且 CI 不含 0） | cap40：r(施法₉,效用)=**+0.022 [−0.148,+0.187]**；cap120：**−0.002 [−0.231,+0.172]**；且 r(施法₉,Σ₉) 变成 **−0.157 / −0.199** | **不成立**（方向都不对：金币放开后「多施法」与更强战团**负相关**） |
| 3 | 金币是绑定约束 → 放开金币即可放大缩放 | ∞金币确实把名次 5.27→2.70、Σ₉ 336→1113、Σ₁₂ 840→1849；但每多一次施法换来的 Σ 从 +3.1 掉到 **−19.8**（cap120 −92.1） | **不成立**（金币不是绑定约束；绑定的是**每回合 40 个动作 + 7 个席位**，法术与随从抢同一份动作预算） |
| 4 | 奖励在很大范围内是平的（阈值型） | **t12 口径成立**：1x 活到 t12 的 61 局，Σ 385→1558（**4.05×**）只换来名次 **4.167→3.857（Δ−0.31）**，utility~log1p Σ₁₂ 斜率 +0.154 **[−0.013,+0.312]（CI 含 0）**；但 t9 口径**不成立**（Δ名次 −1.32 @3.67×） | **部分成立**：只在「自身远低于大厅（1x 的 t12）」和「自身远高于大厅（∞金币上限）」两端平台；中间段（相对强度 0.7–2.0×）是陡的 |
| 5 | 缩放机制本身有产能（不是引擎缺失） | 局内面板（game FE）：1x **+20.5 Σ/次施法 [+17.0,+23.6]**（控制买牌数 +17.1 [+14.7,+19.7]）；但跨局分配效应 +3.1 [−0.3,+6.4] ≈ 0 | **机制有产能、分配无收益**：法术是「等价替换」而不是「复利放大器」 |

**可学梯度 = ∂奖励/∂行为 = (∂奖励/∂身材)·(∂身材/∂行为)。** 数据里
∂奖励/∂身材 很大（r≈0.31–0.40，处处成立），∂身材/∂施法 在 1x ≈ 0、在 ∞金币 ≤ 0，
所以乘积 ≈ 0。**结论：终局名次奖励对缩放行为没有可学梯度；缺的不是金币，是「缩放载体 +
动作预算」。**

## 1. 方法

### 1.1 驱动：训练分布复刻，不训练、不搜索

用训练采集的**同一条代码路径**驱动（`hsbg/az/train/ppo.py::PPOSelfPlayPolicy`，`behavior=net`、
`temperature=1.0`、`move_guard=1`、`move_cap=3`、`move_repeat_limit=2`、
`max_actions_per_turn=40`），对手分布按 s15 采集参数复刻（`runs/az_entity_s15/history.jsonl`
的 header）：

| 项 | s15 采集 | 本实验 |
|---|---|---|
| 人类战团注入 | `human_boards=library_real_quasi_full.jsonl`、`human_board_p=0.9`、`human_board_seats=5`、`sample=auto`、`fidelity=full`、`set_tier=1`、`fast_inject=1` | 同（每新回合、任何座位行动前注入，镜像占用的座位让路） |
| 回合末快照镜像 | `mirror_snaps=runs/library/snaps_champ`、`mirror_seats=2`、`mirror_p=0.2`、`sample=p75` | 同 |
| 其余座位 | 引擎 bot（`game.bot_play`） | 同 |
| 引擎调用顺序 | 每 pass 每座位一次动作；新回合注入 → 座位 0..7 | 同（逐位复刻 `parallel_collect._one_game` + lockstep 的注入序） |

驱动脚本：`scripts/scaling_signal_probe.py`（本轮新增，纯离线，不改引擎/训练）。

### 1.2 快照：施法计数是**引擎直接给的**，不是推断

每个 turn 在 learner **提交 EndTurn 之前**（= 招募结束、战斗之前，与真实库
`recruitment_end_at_phase_switch` 同口径）取一次 `Game.player_json(0)`（约 0.13 ms），记录：

| 字段 | 来源 | 说明 |
|---|---|---|
| `tavern_spells_cast` | 引擎 `PlayerStats` | **酒馆法术施放次数**（本局累计）→ 「施法次数」主口径 |
| `spells_cast` / `spellcraft_cast` | 引擎 `PlayerStats` | 全部法术 / Spellcraft |
| `golden_played` | 引擎 `PlayerStats` | 金色随从生成/打出次数（三连）；另有 `golden_on_board` 快照 |
| `tavern_atk,tavern_hp` | 引擎 `PlayerStats` | **酒馆永久 buff 的累计幅度**；触发**次数**引擎不暴露 → 用「累计值在某个 turn 首次变大」当代理（`tavern_turns9`），已在局限中标注 |
| `minions_bought,cards_played,gold_spent_total,refreshes,combats_*` | 引擎 `PlayerStats` | 活动量/经济混杂控制 |
| `strength,count,tier,gold,health,alive,board_cards` | `PlayerStats` + board | 战团 Σ(atk+hp)、载体识别（见 §2.3） |
| `opp_mean,opp_max,opp_strengths` | `Game.view(0)["opponents"][*]["board"]` | 7 席对手**当前**战团 Σ（离线诊断用，**不是**策略观测） |

合计 **860 局实验**（`rollouts/` 里 11 个 tag / 1,260 行，其中 `real`、`gold99` 各有一份同 seed
复现副本）、约 **1.04 万个 turn 快照**（原始行 15,241）；截断 0 局、异常 0 局
（`truncated=false` / `errors: 0`；策略给出非法动作时会兜底到首个合法动作，本实验未记录到触发）。

### 1.3 九个 arm（同一权重，只改经济/动作预算）

| arm | 局数 | 金币 | 动作上限 | 用途 |
|---|---:|---|---:|---|
| `real` / `real_opp` | 200 | 1x（真实） | 40 | 对照组（`_opp` = 额外记对手战团，同 seed 同结果） |
| `gold99` / `gold99_opp` | 200 | 每回合设 99 | 40 | **∞金币课程**（题面口径，= `engine_ceiling_probe --cheat gold`） |
| `gold99_cap120` | 100 | 99 | 120 | 「更松的动作预算」上限档（ceiling probe 口径） |
| `dose_g12/15/20/30/50/99` | 60 ×6 | 12/15/20/30/50/99 | 40 | **金币剂量曲线**（「课程开多大」） |

同一 seed 基址（`880000`）→ real 与 gold99 是**配对**的（同大厅、同配牌、同注入 RNG）。

### 1.4 统计口径

- 名次 1..8 → 效用 `u = 1 − 2(r−1)/7`（与 `hsbg/az/train/common.py::RANK_UTILITY` 一致；
  与原始名次的相关系数**符号相反**——`corr(施法, 名次) = −corr(施法, 效用)`）。
- Pearson + Spearman（=秩上 Pearson）+ **局级 bootstrap**（B=4000、percentile 95% CI、固定种子 20261031）。
- 部分相关：秩残差法（控制「活到第几回合」`death_turn` 与「前 9 回合花钱」`gold_spent9`）。
- 稳健性：只用「活到 t9 招募末」的局（`full9`，消除「死得早 → 累计施法自然少」的机械混杂）。
- 局内面板：`ΔΣ_t ~ Δ施法_t` 的**局内去均值 OLS**（game fixed effects）+ 按局 cluster bootstrap
  （`scripts/scaling_signal_panel.py`）。

### 1.5 可复现性

同 seed 两次独立运行（10 worker vs 8 worker，两个进程组）逐局 **bit-identical**：
`real` vs `real_opp` **200/200 局完全相同**、`gold99` vs `gold99_opp` 200/200 相同
（去掉 v2 新增的对手字段后逐字段相等）。→ 驱动是确定性的，唯一变量是 `--gold` / `--max-actions-per-turn`。

### 2.3 「缩放载体」：为什么施法不复利

引擎里「Whenever you cast a spell on this …」类随从（`catalog_json` 全表匹配）共 5 张 ×
普通/金色 = 10 个 id，再加 Felboar `BG28_633`（法术吞食酒馆随从）= **11 个 id**：

| 卡 | tier | 效果 |
|---|---|---|
| **Devilish Distractor** `BG36_762`(+`_G`) | 5 | 对其施法 → 酒馆随从**本局永久 +1/+2**（金色 +2/+4）——**唯一的永久复利引擎** |
| Twilight Tidehunter `BG36_703`(+`_G`) | 4 | 对其施法 → 手牌最左随从 +8/+8（金色 +16/+16） |
| Vigilant Bristlemane `BG36_510`(+`_G`) | 5 | 对其施法 → 对相邻随从打血宝石 |
| Gatekeeper Amalgam `BG36_640`(+`_G`) | 6 | 对其施法 → 再施放 Misplaced Tea Set |
| Fleeing Fugitive `BG36_921`(+`_G`) | 1 | 对其施法 → +1 生命（金色 +2） |
| Felboar `BG28_633` | – | 施放 3 个法术后吞食酒馆随从获得其身材 |

这些是 ceiling probe 里 t12 从 257 → 1843 的**唯一机制**。三个主 arm（500 局）里：

- 曾在 t9 在场：**1x 6.0% / ∞金币 8.0% / cap120 9.0%**；
- 前 9 回合平均在场回合数：0.44 / 0.55 / 0.72 回合。

即 **>90% 的局从头到尾没有拿到载体**，施法只能换来一次性加身材（"+2/+2 你的随从" 之类），
没有永久复利。这解释了表 B 里 `casts→Σ` 的斜率为什么 ≤0。

cap120 把动作放开到 120 后，每次施法相对身材的边际值直接变成 **−36 ~ −45 Σ**（黄金全用在
买随从/升级比施法更划算，而且此时它已经 tier 6 + 千级身材）。

## 7. 判定

1. **终局名次奖励对缩放行为没有可学梯度 —— 成立。** 三个主 arm、8 个经济档位的
   `corr(前9回合施法次数, 最终名次效用)` 都落在 [−0.15, +0.12]，全部 CI 含 0；
   1x 的微弱正相关在控制存活后归零（−0.019）；`corr(施法, 战团身材)` 在 ∞金币下显著**为负**
   （−0.157 / −0.199）。按题面判据：**「CI 含 0 且 |r|<0.1」——CI 含 0 成立，
   |r|=0.115 略高于 0.1（Spearman 0.139 刚好擦线），实质是「测不到可学梯度」。**
2. **∞金币课程把信号变成可学 —— 不成立。** 题面判据要求 r>0.3 且 CI 不含 0；
   实测 cap40 **+0.022 [−0.148,+0.187]**、cap120 **−0.002 [−0.231,+0.172]**。
   金币课程改变的是**水平**（名次 5.27→2.70，Σ₉ 0.62→2.03×，配对同 seed：名次 −2.57
   [−2.81,−2.35]，179/200 局更好），不是**信用分配**。
3. **「奖励是纯阶梯、在大范围内平」——部分成立。** 平台在**两端**：1x 的 t12
   （4.05× 身材 → 0.31 名次，斜率 CI 含 0）与 ∞金币的上平台（rel9 3.5→11.6，Δ名次 −0.25）；
   中间段（rel 0.7–2.0）奖励很陡（Δ名次 −1.4 ~ −1.6）。
   **s15 在 1x 坐在下平台、∞金币把它推到上平台——两头都不在陡区。**
4. **机制诊断：缺的不是金币，是「缩放载体 + 动作预算」。** 只有当棋盘上有
   `cast a spell on this`（5 张 / 10 个 id）或 Felboar 时法术才复利；`500` 局里 6–9% 的局拿到过。
   没有载体时，一次施法与一张随从是**等价替换**（局内 +20 Σ/次 只是「这一回合宽裕」的
   关联，跨局 +3.1 Σ/次 CI 含 0），所以「多施法」在奖励里没有正期望。

## 8. 对「∞金币课程该开多大 / 多久」的定量建议

**尺寸：不要开 99，开到 `--curriculum-gold-mult ≈ 2–3`（≈20–30 金/回合）就够，而且这一步
本身不足以学会缩放。**

- 剂量表给出映射：金币 12/15/20/30/50/99 ⇒ Σ₉/真实p50 = 0.83/1.17/1.36/2.01/2.23/2.12×，
  名次 3.73/3.27/3.12/**2.67**/2.73/2.50。
- 名次在 **30 金/回合**之后饱和（2.67→2.50，top4 98%→100%，Σ₉ 还在涨 11%）——再往上加金币
  只是把奖励推到天花板、把效用方差从 0.41 压到 0.24，**对学习有害**。
- 想让「自身 ≈ 大厅」出现在**关键回合**（t11–t13，人类在 t12 是 4458、t13 是 9446），需要
  Σ₁₂ 从现在的 840 提到 3000–6000：剂量表里 gold 30–50 的 Σ₁₂ p50 是 1673–2163，gold99 cap120
  是 5486 ⇒ **mult 3–5 覆盖上限**。
- **但尺寸解决不了本报告的问题**：9 个档位里 `r(施法,效用)` 都没打开。金币课程必须与
  `docs/CURRICULUM_SCALING.md` 的 C/D 臂**同时开**：
  `--teacher-bc-coef`（教「买载体 + 把法术打在载体上」）+ `--process-value-coef`（施法数 /
  酒馆永久 buff / consume 的过程价值），否则策略只会把多出来的金币换成**随从与 tier**
  （这正是本轮观察到的：Σ 涨了 3–11×，施法占比与施法收益没变）。

**时长：不是卡在样本量上，而是卡在「载体行为要被采样到」。**

- 样本量算术（用本轮实测的噪声）：每局效用 sd = 0.27–0.41，前 9 回合施法 sd = 4.7–9.4。
  一个 δ=+0.01 效用/次的真实效应在 192 局/iteration 下的 SNR ≈ δ·σ_c·√192/σ_u ≈ **1.6σ**
  ⇒ **1–2 个 iteration 就能学到**；要用回归 2σ 分辨 δ=0.01 只需 **~300 局**（≈1.5 iteration）。
  所以「训练不够久」不是解释——本报告用了 **860 局实验**（1,260 行），δ 仍 ≈0。
- 真正需要的是**带载体的局数**：载体率 6–9%，192 局/iteration ⇒ 每 iteration 只有 **~15 局**
  带载体。要把载体的价值（ceiling probe 口径：t12 257→1843，≈+0.5~0.9 效用）学到手，
  需要 **200–400 个带载体回合/样本** ⇒ **13–26 个 iteration**；若教师把载体率提到 25–30%，
  可压到 **3–5 个 iteration**。按当前 ≈3,700 s/iteration（192 局、29k decisions），
  即 **约 5–10 小时（教师开）/ 15–25 小时（只开金币）**。
- **停止/退火判据**（在 1x 复评里同时满足）：① `carrier9_frac ≥ 25%`；② 1x 下
  `施法₉ ≥ 20` 且不塌；③ `r(相对强度, 效用) ≥ 0.3`（当前 0.317，已满足）**且**
  `r(载体在场回合数, Σ₁₂) > 0`（当前 −0.14，**这是唯一还没过的门**）。过了这道门再线性退火
  到 mult=1（`--curriculum-stage anneal`）。

## 9. 局限

1. **施法/金色计数是引擎原生计数器，不是推断**（`PlayerStats.tavern_spells_cast` /
   `spells_cast` / `golden_played`），可信；但**酒馆永久 buff 的「触发次数」引擎不暴露**，
   只有累计幅度 `tavern_atk/tavern_hp`，本报告用「累计值首次变大的回合数」当代理
   （`tavern_turns9`，1x 均值 0.23 回合）——**这是代理，不是真实触发计数**。
   「金色化」同理：`golden_played` 是生成/打出计数，三连触发次数未单独暴露。
2. **t12 / t15 口径有存活选择**：1x 只有 **61/200** 局活到 t12 recruit（t15 只有 **3 局**），
   所以 §4.1 的 t12 十分位每桶 5–8 局、CI 很宽；t15 无法做统计（仅作描述）。
   为此本报告额外给了无存活截断的 t9 口径（`ratio9` / `rel9`，n=186–200）。
3. **载体子集太小**（9–16 局）：表 C2 只能说「没观察到」，不能说「一定没有」。
4. **样本量**：主 arm 200/200/100 局，剂量臂各 60 局（CI 宽度约 ±0.2–0.3 对 r）。
   1x 的 r=+0.115 的 CI [−0.023,+0.246] 意味着「真实梯度最多 ~0.02 效用/次」——不能排除
   **很小**的正效应，但可以排除「课程能把它放大到可学」。
5. **这是关联分析，不是因果学习实验**：本报告没有训练，所有「学不到」都是从
   `∂奖励/∂行为`、`∂身材/∂行为` 与噪声尺度推断；PPO 实际的优势估计未直接测量。
6. **对手分布是复刻**（5 席人类战团 p0.9 + 2 席镜像 p0.2 + bot），不是训练时逐 iteration 的
   真实采样（不同 iteration 的 mirror 快照池会变）；本实验固定用 s15 的配置与
   `runs/library/snaps_champ`。1x 的 mean rank 5.27 与训练侧 `human_mean_rank 6.32`
   （iteration 492 的 eval）同量级，说明复刻合理。
7. **每回合 40 动作上限**是训练/竞技场口径；`cap120` 只是「更松」的对照，不是线上规则。
